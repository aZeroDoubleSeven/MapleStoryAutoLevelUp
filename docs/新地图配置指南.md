## 1. 概述

### 1.1 配置清单

在一张新地图上运行自动练级机器人，所需的配置项如下：

| 功能 | 是否必须配置 | 说明 |
|------|-------------|------|
| 路线图 | **必须** | 定义移动路径（除非使用 patrol 巡逻模式） |
| 怪物检测 | 可选 | 默认使用 `contour_only` 模式，无需配置 |
| 小地图玩家颜色 | 推荐 | 用于定位玩家在地图上的位置 |
| HP/MP 监控 | 可选 | 默认已启用，使用自动检测 |
| 符文配置 | 可选 | 默认已配置常见符文 |

### 1.2 配置方式

本项目提供**两种配置方式**：

| 配置方式 | 说明 | 适用场景 |
|----------|------|----------|
| **UI 界面配置** | 通过图形界面操作，简单直观 | 大多数配置项，推荐新手使用 |
| **YAML 文件配置** | 直接编辑配置文件 | 高级配置、批量修改 |

**推荐做法**：使用 UI 界面进行基础配置，需要时再编辑 YAML 文件进行高级调整。

### 1.3 工作原理简述

```
┌─────────────────────────────────────────────────────────────────┐
│                        游戏画面截图                              │
└──────────────────────────────┬──────────────────────────────────┘
                               │
                               ▼
┌─────────────────────────────────────────────────────────────────┐
│                      图像处理流程                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. 小地图检测 (get_minimap_loc_size)                           │
│     → 通过白色边框定位小地图在屏幕上的位置                         │
│                                                                  │
│  2. 玩家位置检测 (get_player_location_on_minimap)               │
│     → 在小地图中查找指定颜色的像素点作为玩家位置                    │
│                                                                  │
│  3. 路线图匹配 (get_nearest_color_code)                         │
│     → 在玩家周围搜索最近的路线颜色，返回移动命令                    │
│                                                                  │
│  4. 怪物检测 (get_monsters_in_range)                            │
│     → 在攻击范围内检测怪物轮廓或使用模板匹配                       │
│                                                                  │
│  5. 命令执行 (KeyBoardController)                               │
│     → 将命令转换为键盘输入                                        │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

## 3. 目录结构

### 3.1 地图资源目录

每个地图需要创建以下目录结构：

```
minimaps/
└── {地图名}/                    # 地图名称，英文小写，下划线分隔
    ├── route_map.png           # 路线图（必需，除非用 patrol 模式）
    ├── mobs/                   # 怪物模板目录（可选）
    │   ├── monster1.png
    │   ├── monster2.png
    │   └── ...
    └── rune/                   # 符文模板目录（可选）
        ├── rune_warning_cn.png  # 符文警告消息模板（中文）
        ├── rune_warning_eng.png # 符文警告消息模板（英文）
        ├── rune_enable_cn.png   # 符文激活消息模板（中文）
        ├── rune_enable_eng.png  # 符文激活消息模板（英文）
        ├── rune_part1.png       # 符文图标部分1
        ├── rune_part2.png       # 符文图标部分2
        ├── rune_part3.png       # 符文图标部分3
        ├── arrow_left.png       # 左箭头模板
        ├── arrow_right.png      # 右箭头模板
        ├── arrow_up.png         # 上箭头模板
        └── arrow_down.png       # 下箭头模板
```

### 3.2 配置文件

在 `config/config_custom.yaml` 中添加地图相关配置：

```yaml
bot:
  map: {地图名}                  # 必须与 minimaps 下的目录名一致

route:
  map: {地图名}                  # 地图标识

minimaps:                        # 地图资源路径
  {地图名}:
    route_map: minimaps/{地图名}/route_map.png
    mobs_dir: minimaps/{地图名}/mobs/
```

## 4. 准备工作

### 4.1 工具清单

| 工具 | 路径 | 用途 |
|------|------|------|
| 路线录制器 | `tools/routeRecorder.py` | 半自动录制路线图 |

### 4.2 环境要求

1. 游戏以**窗口模式**运行（不是全屏）
2. 游戏窗口标题与配置一致：`cfg["game_window"]["title"]`
3. 屏幕分辨率为 16:9 比例
4. 小地图必须可见且在屏幕左上角区域

### 4.3 初始配置检查

在开始配置前，确保 UI 界面中的以下配置正确：

#### 通过 UI 配置

1. **启动程序**：`python -m src.main`
2. **点击 Load Config** 加载 `config_custom.yaml`
3. **选择地图**：在 Map 列表中选择目标地图
4. **检查 Advanced Settings** 标签页中的配置

#### 通过 UI 配置游戏窗口（高级设置）

在 Advanced Settings 标签页中找到 `game_window` 分组：

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `title` | 游戏窗口标题 | "MapleStory Worlds" |
| `size` | 窗口尺寸 | [693, 1282] |

## 6. 路线图制作

### 6.1 原理说明

路线图是一张与游戏地图尺寸相同的 PNG 图片，使用不同颜色标记移动路径。机器人会在玩家周围搜索最近的路线颜色，根据颜色对应的命令移动。

**核心逻辑** (`get_nearest_color_code` 方法)：

```python
# 伪代码
for y in range(player_y - search_range, player_y + search_range):
    for x in range(player_x - search_range, player_x + search_range):
        pixel = img_route[y, x]  # 获取像素 RGB 值
        distance = abs(x - player_x) + abs(y - player_y)  # 曼哈顿距离
        
        # 查找匹配的颜色代码
        if pixel in color_code:
            # 记录距离最近的匹配
            ...
```

### 6.2 颜色编码详解

| 颜色 (RGB) | 显示效果 | 命令格式 | 说明 |
|------------|---------|----------|------|
| `255,0,0` | 红色 | `left none none` | 向左移动 |
| `0,0,255` | 蓝色 | `right none none` | 向右移动 |
| `255,127,0` | 橙色 | `left none jump` | 向左跳跃 |
| `0,255,255` | 青色 | `right none jump` | 向右跳跃 |
| `127,255,0` | 黄绿色 | `none down jump` | 下跳（跳下平台） |
| `255,0,255` | 紫红色 | `none none jump` | 原地跳跃 |
| `0,255,127` | 浅绿色 | `stop stop stop` | 停止 |
| `255,255,0` | 黄色 | `none none goal` | 目标点（切换路线） |
| `255,0,127` | 粉色 | `none up teleport` | 向上传送 |
| `127,0,255` | 紫色 | `none down teleport` | 向下传送 |
| `0,127,0` | 深绿色 | `left none teleport` | 向左传送 |
| `139,69,19` | 棕色 | `right none teleport` | 向右传送 |

**上下移动专用颜色**（绳索攀爬）：

| 颜色 (RGB) | 显示效果 | 命令格式 | 说明 |
|------------|---------|----------|------|
| `127,127,127` | 灰色 | `none up none` | 向上爬绳 |
| `255,255,127` | 浅黄色 | `none down none` | 向下爬绳 |

### 6.3 使用路线录制器（推荐）

#### 步骤 1：创建地图目录

```bash
mkdir minimaps\{地图名}
mkdir minimaps\{地图名}\mobs
```

#### 步骤 2：启动路线录制器

```bash

```

录制器界面会显示游戏画面，左侧面板用于选择颜色和命令。

#### 步骤 3：录制路线

```
┌─────────────────────────────────────────────────────────────────┐
│  路线录制器操作说明                                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  鼠标左键：涂抹当前选择的颜色                                     │
│  鼠标右键：擦除                                                  │
│                                                                  │
│  快捷键：                                                       │
│    1-9      选择预设颜色（对应颜色编码表）                        │
│    0        擦除模式                                             │
│    S        保存路线图                                            │
│    Q        退出                                                  │
│                                                                  │
│  推荐录制顺序：                                                  │
│    1. 先用移动颜色（红/蓝）标记主要路径                           │
│    2. 在需要跳跃的位置用跳跃颜色（橙/青）                         │
│    3. 在传送点用传送颜色（深绿/棕色）                             │
│    4. 在绳索处用上下移动颜色（灰/浅黄）                           │
```

### 6.4 手动制作路线图

如果无法使用录制器，可以手动创建：

#### 方法 1：截图+编辑

1. 在游戏中截取地图截图
2. 使用图像编辑软件（如 Photoshop、GIMP）绘制路线
3. 确保颜色精确匹配编码表

#### 方法 2：从现有路线图修改

1. 复制一个相似地图的路线图
2. 根据需要修改颜色区域

### 6.5 制作注意事项

| 注意事项 | 说明 |
|----------|------|
| **颜色必须精确** | RGB 值必须与配置完全一致，不支持近似匹配 |
| **避免杂色** | 路线区域应该是纯净的纯色，不要有渐变或抗锯齿 |
| **路线宽度** | 建议 5-10 像素宽，便于机器人准确检测 |
| **搜索范围** | 如果路线间距小于 `route.search_range`（默认 10 像素），可能导致误匹配 |
| **绳索处理** | 爬绳时建议同时放置移动颜色和上下颜色，确保平滑过渡 |
| **目标点** | 在路线终点放置 `goal` 颜色，可以触发路线切换 |

### 6.6 高级技巧

#### 绳索攀爬路线设计

```yaml
# 在绳索区域同时放置两种颜色：
# - 主路径颜色（如蓝色 right）
# - 上下移动颜色（灰色 up）
# 机器人会根据距离自动判断使用哪个
```

#### 边缘传送配置

```yaml
edge_teleport:
  enable: True                  # 启用边缘检测
  color_code: [255, 127, 127]  # 边缘悬崖颜色
  trigger_box_width: 20        # 检测框宽度
  trigger_box_height: 10       # 检测框高度
```

在路线图中用 `(255,127,127)` 标记悬崖边缘，机器人会自动传送避免跌落。

## 7. 怪物检测配置

### 7.1 检测模式对比

| 模式 | 是否需要模板 | 速度 | 准确性 | 推荐场景 |
|------|-------------|------|--------|----------|
| `contour_only` | **不需要** | 快 | 中 | 默认推荐，新地图首选 |
| `template_free` | 不需要 | 最快 | 低 | 性能敏感场景 |
| `grayscale` | 需要 | 中 | 高 | 模板质量好时使用 |
| `color` | 需要 | 慢 | 最高 | 模板质量非常好时使用 |

### 7.2 Contour Only 模式（默认，无需配置）

这是**默认模式**，不需要任何怪物模板。原理是检测游戏中的黑色描边轮廓。

#### 工作原理

```
┌─────────────────────────────────────────────────────────────────┐
│                   contour_only 模式检测流程                       │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. ROI 定义                                                    │
│     根据玩家位置和攻击范围确定搜索区域                              │
│     排除玩家角色自身区域                                          │
│                                                                  │
│  2. 黑色像素提取                                                 │
│     图像 == (0,0,0) → 白色掩码                                   │
│     其他像素 → 黑色掩码                                           │
│                                                                  │
│  3. 高斯模糊 (blur=5)                                           │
│     平滑边缘，减少噪声干扰                                        │
│                                                                  │
│  4. 模板匹配 (TM_SQDIFF_NORMED)                                 │
│     与内置的黑色轮廓模板匹配                                       │
│                                                                  │
│  5. NMS 非极大值抑制                                             │
│     iou_threshold=0.4，合并重叠检测框                             │
│                                                                  │
│  6. 血条辅助验证 (可选)                                          │
│     绿色 (71,204,64) 像素连通域，确认怪物存活                      │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

#### 配置项说明

```yaml
monster_detect:
  mode: "contour_only"         # 检测模式
  diff_thres: 0.8              # 匹配阈值（越小越严格）
  search_box_margin: 50        # 搜索框额外边距
  contour_blur: 5               # 高斯模糊核大小
  with_enemy_hp_bar: True      # 启用血条辅助验证
  hp_bar_color: [71, 204, 64]  # 怪物血条颜色（BGR）
```

**阈值调整建议**：

| 场景 | diff_thres 推荐值 |
|------|-------------------|
| 误检多（检测到非怪物） | 0.6 - 0.7 |
| 默认 | 0.8 |
| 漏检多（检测不到怪物） | 0.85 - 0.9 |

### 7.3 模板匹配模式

如果 `contour_only` 模式效果不佳，可以切换到模板匹配模式。

#### 制作怪物模板

##### 步骤 1：截取怪物图像

1. 在游戏中找到目标怪物
2. 使用 `tools/getPixeColorOnImg.py` 或截图工具截取怪物图像
3. 保存为 PNG 格式

##### 步骤 2：图像处理要求

| 要求 | 说明 |
|------|------|
| **尺寸** | 建议 30-100 像素 |
| **背景** | 使用 `get_mask()` 函数处理，绿色 `(0,255,0)` 区域视为透明 |
| **质量** | 避免过度压缩，使用无损格式 |
| **数量** | 同一怪物建议准备 2-3 个不同角度的模板 |

##### 步骤 3：透明背景处理

怪物模板的背景需要特殊处理才能被正确匹配：

```python
from src.utils.common import get_mask, load_image

# 加载模板图像
template = load_image("monsters/ghost.png")

# 生成掩码：绿色 (0,255,0) 区域将被忽略
mask = get_mask(template, ignore_pixel_color=(0, 255, 0))

# 或者创建仅保留黑色轮廓的掩码
mask = get_mask(template, ignore_pixel_color=(0, 255, 0))
```

**图像处理规范**：

| 区域类型 | 处理方式 |
|----------|----------|
| 怪物轮廓 | 保留原始像素 |
| 透明区域 | 填充绿色 `(0,255,0)` |
| 内部细节 | 可以透明也可以保留 |

## 9. HPMP监控配置

### 9.1 原理说明

健康监控系统通过分析游戏画面中的 HP 条、MP 条和 EXP 条来监控角色状态：

```
┌─────────────────────────────────────────────────────────────────┐
│                    HP/MP 监控检测流程                            │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  1. 灰度化 + 白色掩码                                             │
│     提取纯白色像素（空白条区域）                                   │
│                                                                  │
│  2. 连通域分析                                                    │
│     找所有白色连通区域                                             │
│                                                                  │
│  3. 筛选条形区域                                                  │
│     宽高比 4 < w/h < 10                                           │
│     面积 2500 < w*h < 5000                                       │
│                                                                  │
│  4. 按 X 坐标排序                                                 │
│     HP条(左) → MP条(中) → EXP条(右)                              │
│                                                                  │
│  5. 计算填充比例                                                  │
│     白色边界内灰色像素占比 = 未填充比例                            │
│     100% - 未填充比例 = 填充比例                                  │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 9.2 血条百分比计算

```python
def get_bar_percent(img):
    """
    计算条形填充百分比
    
    原理：
    1. 找到左右白色边界（条形框）
    2. 统计边界内的灰色像素数量（未填充部分）
    3. 填充比例 = (总宽度 - 未填充像素) / 总宽度
    """
    line_pixels = img[h // 2, :]  # 取水平中线
    
    # 灰色判定：RGB 值相近且非黑
    if abs(r - g) <= 10 and abs(r - b) <= 10 and r > 0:
        unfill_pixel_cnt += 1
    
    fill_ratio = (total_width - unfill_pixel_cnt) / total_width * 100
```

## 13. 常见问题排查

### 13.1 玩家位置检测问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 检测不到玩家位置 | 小地图没有白色边框 | 确保小地图可见且有边框 |
| 玩家位置偏移 | `player_color` 不准确 | 使用工具重新获取颜色值 |
| 检测到错误位置 | 颜色在小地图中不唯一 | 调整 `player_color` 或加入队伍 |
| 位置跳动不稳定 | 玩家点太小或有噪声 | 增大 `offset` 修正 |

### 13.2 路线图问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 角色不走路线 | 颜色不匹配 | 确保路线图颜色精确匹配配置 |
| 角色乱走 | 搜索范围太小 | 增大 `route.search_range` |
| 角色卡在绳索 | 上下移动颜色缺失 | 在绳索区域添加上下颜色 |
| 不切换路线 | 缺少 `goal` 颜色 | 在路线终点添加黄色标记 |

### 13.3 怪物检测问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 误检多（检测到空气） | 阈值太高 | 降低 `diff_thres`（如 0.7） |
| 漏检多（检测不到怪物） | 阈值太低 | 提高 `diff_thres`（如 0.85） |
| 检测到非怪物物体 | 背景复杂 | 启用 `with_enemy_hp_bar: True` |
| 模板匹配不准 | 模板质量差 | 重新制作高质量模板 |

### 13.4 符文问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 不进入符文状态 | 警告消息检测失败 | 检查 `rune_warning_cn/eng` 坐标 |
| 找不到符文图标 | 模板不匹配 | 重新截取符文图标模板 |
| 箭头输入错误 | 箭头模板不准 | 重新截取箭头模板，增加变体 |
| 一直停留在 `near_rune` | 触发距离太大 | 减小 `rune_trigger_distance_x/y` |

### 13.5 HP/MP 监控问题

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 不喝药 | 药水键配置错误 | 检查 `key.add_hp/add_mp` |
| 一直喝药 | 阈值太低 | 提高 `add_hp/add_mp_percent` |
| 冷却中仍然喝药 | 冷却时间未生效 | 检查 `add_hp_cooldown` 配置 |
